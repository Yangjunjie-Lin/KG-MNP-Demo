# 本体建模模块说明

> 文档日期：2026-09-16。代码审查基线：`develop@194e091d13cabba5833ff1d531f814858ea968ae`。
> 本文件保留原方案的职责与组织。2026-09-16 已增量实现输入适配、原生绑定结果出口、受控轨迹与服务下载；实际验证和剩余限制见 [实施记录](IMPLEMENTATION_STATUS.md)，不把下方原审查基线误作当前状态。

## 1. 一句话定位

本体建模模块接收规则化数据及其来源，在冻结的业务范围内，通过两个计算型 Agent 完成五阶段建模，复用现有内核生成可验证、可回查的本体成果，并向演进组提供本模块真实运行的过程与评价材料。

**本模块交两类东西：建出了什么，以及具体怎样建出来、哪里出错。**

原生 `.kgop` 是现有项目的本体归档格式；逐文件交接视图方便组员使用；演进 JSONL 用于记录运行。三者不是互相改扩展名的同一种格式。

## 2. 三组分工

| 责任方 | 应负责的内容 | 不应被要求承担的内容 |
|---|---|---|
| 数据处理组 | 规则化记录/文本、原始来源定位、质量结果、数据批次封面；提供授权可访问的来源快照 | 不预造本体候选、稳定本体 IRI、编译计划、建模审批或模型标准答案 |
| 本体建模组 | 范围冻结、语义复用、映射与事实、校验审核对接、确定性编译、结果导出、本模块 Agent 轨迹埋点 | 不重做上游清洗；不自行完成演进模型训练、策略搜索、上线或回滚 |
| 演进组 | 收集运行与评价、形成反馈/训练资料、提出改进、执行其自身演进流程 | 不直接改写已批准本体；本体修订仍回到本模块形成新版本并重新验证 |

业务负责人确认 `goal_and_rules.json`；平台或领域包管理方提供可选基线与依赖锁；验收负责人独立提供预期答案。它们不全部属于数据处理组。

演进文档中的“上游”是**向演进框架提供运行数据的一方**，与本模块所称的“上游数据处理组”不是同一个角色。业务审批、Action 执行的轨迹由相应业务执行模块产生，不能由本体建模组补造。

## 3. 输入：保留原交接包的组织

当前编号遵循 01–08 输入、09–14 本体成果、15–17 演进数据，完整对应表只维护在
[需求追踪](../../requirement_traceability.md#2026-09-18-0117-统一对应表)。以下文件说明不扩展编号。
S1 冻结输入及职责，S2/S3 产生候选与真实执行依据，S4 校验并由授权人审核，S5 复用
共享编译和原生归档产生 09–14；15 随真实调用采集，16 由授权真人提交，17 在批次最后生成。

| 文件 | 提供方 | 必要性与用途 |
|---|---|---|
| `records.json` | 数据处理组 | 有结构化数据时提供；包含记录、字段、值及来源引用 |
| `text_blocks.json` | 数据处理组 | 有文本时提供；保留冻结文本、版本与定位引用 |
| `source_locator.json` | 数据处理组 | 数据/事实需要溯源时提供；将字段和引文定位到来源快照 |
| `quality_report.json` | 数据处理组 | 说明已经执行的质量检查及未解决异常 |
| `manifest.json` | 上游交接整合方 | 绑定批次、文件摘要及访问范围；不是原生 ModelingInputBundle |
| `goal_and_rules.json` | 业务负责人，建模阶段确认 | 建模范围、身份/时间规则、业务约束及能力问题；不混入隐藏答案 |
| `baseline.ttl`、`imports.lock.json` | 平台/领域包管理方 | 有可复用本体时提供；没有时明确无基线，不伪造 |
| `acceptance_private/expected_answers.json` | 验收负责人 | 有独立验收任务时提供；不能供生成和修复模型读取 |

`sources/` 和 `assets/` 是所需依赖，不再扩成一长串主业务文件。原始来源无法随包复制时，应给出授权可解析引用并明确外部依赖，不虚称完全自包含。

交换输入经薄适配进入已有 `Source/Batch/Plan/Run → KG-IR/Evidence → modeling.session`。不能将整个 `mapping.json` 当成已有请求 DTO，也不能手写原生运行 ID 来跳过接入。

## 4. 五阶段与两个 Agent

2026-09-17 工作台已将以下归属封装成两个 Agent 卡片，RuleAgent 显示名为“规划 Agent”。
真实子调用复用原角色入口；新增前后文件和受控下载，见 [逐步审计](AGENT_STEP_AUDIT.md)。
不增加第三个计算角色或批准权。

保持当前代码命名：`RuleAgent` 和 `TaskExecutionAgent`。后者是本体建模中的执行角色，不是下游业务 Action Agent。

| 阶段 | 计算角色 | 本阶段具体做什么 | 应保留的交接依据 |
|---|---|---|---|
| S1 输入核验与范围确认 | RuleAgent | 检查数据、来源、质量与目标，冻结输入、依赖和范围 | 输入快照、范围、质量结果、资源版本；独立答案仅在验收侧 |
| S2 本体复用与结构设计 | RuleAgent | 查找可复用术语，提出类、属性、关系及约束设计 | 检索候选、选择依据、结构候选及模型实际调用 |
| S3 数据映射与事实构建 | TaskExecutionAgent | 将记录/文本转为对象和事实，绑定来源并规范化身份 | 实际映射、候选事实、来源定位、转换收据 |
| S4 联合校验与人工审核 | RuleAgent 负责计算；授权人负责审批 | 运行完整性、SHACL/OWL 等适用检查，分流问题，接受真实审核决定 | 分项验证报告、问题、修复轨迹、原生审核记录 |
| S5 语义编译与交付验收 | TaskExecutionAgent | 复用共享编译与归档内核，重读、复验并导出 | 原生 `.kgop`、逐文件交接视图、导出回执与摘要 |

人类审批不是第三个计算 Agent，也不是由 RuleAgent 代签。研究模式中的有界 S4→S2/S3 修复，不能直接当成生产模式已完成同样能力的证明。

无实例的 CQs-only 任务不得造实例；没有独立合法约束时不能从预测反造 SHACL；依赖缺失记未运行或受阻，不能记通过。

## 6. 输出 B：演进运行交接

| 文件 | 地位 | 说明 |
|---|---|---|
| `executions/run-<id>.jsonl` | 演进契约核心要求 | 一次真实任务/运行一个文件；记录模型与工具调用、失败和重试 |
| `reviews/*.jsonl` | 有真实人工评价时交付 | 评价某一次运行，不是把本体审批文件改名 |
| `upstream_manifest.json` | 对方可选、强烈推荐；本项目拟默认生成 | 用对方指定的 `name / sha256 / size` 字段核对本批轨迹与评价 |

保留两个**可选项目关联附件**：`context/run_bindings.json` 关联外部运行 ID、原生运行/会话/任务/版本与产物；`context/harness_manifest.json` 说明六类 harness 摘要的实际来源。核心协议不依赖它们；有附件时继续检查真实资源和版本，缺失时组合交付关联为 NOT_PROVEN_NO_CONTEXT，不能自动宣称同次产物。它们不增加交付类别，也不表示对方会自动解析。

模型完整消息不能从旧审计哈希还原，应在真实模型边界按权限留存。轨迹不是隐藏思维链：仅记录实际请求消息、公开回复、工具输入输出和运行状态，不记录供应商私有推理字段。
