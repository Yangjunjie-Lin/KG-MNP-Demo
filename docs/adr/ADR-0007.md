# ADR-0007: One audited application service boundary

## Status

Accepted for Prompt 7.

## Decision

Use one explicit operation catalogue behind the local CLI, local SDK, HTTP SDK
and REST API. Authentication is a local bearer-token store that persists only
credential digests. Project authorization is checked before object resolution.
State-changing operations either execute through the same core handler or are
durable jobs in the SQLite job store with idempotency and fencing.

External adapters receive administrator-registered target IDs and an
approval-bound integration plan. They cannot mutate Confirmed Packages,
Packages, Releases, or the P6 EnvironmentPointer.

## Consequences

This keeps HTTP concerns out of lifecycle and semantic code and gives P8 a
stable request/result boundary. Some catalogue items are explicitly blocked
until their underlying core operation is implemented. This is preferable to a
second business implementation in the API or CLI.

The local trust model is single-node and operator-managed. This ADR does not
claim enterprise SSO, OS sandboxing for Python adapters, or live GraphDB/
WebVOWL availability when those external prerequisites are absent.
