# ADR-0008 — Gate the Workbench on a real service workflow

Status: accepted boundary decision; implementation is partial / NO_GO.

P7 declares 53 operations, while its facade implements only a subset and its
project constructor does not create a core Workspace. Binding a UI to those
declarations would misrepresent capability and leave project/job isolation open.

Decision: reuse core Workspace/ProjectLock, validate stable service/core identity
mapping, retain incomplete old records without repairing them implicitly, check
object ownership and active credentials on the server, use scoped durable
idempotency, and reject missing handlers before queue acceptance. The public
catalogue records concrete handler paths and distinguishes unimplemented work.

No arbitrary operation/JSON console is treated as a product workbench. The
default future UI is Chinese, domain-neutral and uses one existing API/service
boundary. UI stack selection, sessions, resource families and browser acceptance
remain unimplemented until the backend gate is passed. No alternate Prompt or
Stage/Phase roadmap is introduced.

Consequences: P8 cannot receive GO; GraphDB licensing is not the reason. Core
commit fencing and all required service adapters must be completed before
resuming formal 8B/8C acceptance. P9 admission remains blocked. Public schema
and pack semantic versions remain unchanged on this partial branch.
