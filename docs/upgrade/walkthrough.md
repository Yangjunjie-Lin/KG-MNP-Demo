# 本地汇报操作

使用 README 的本地演示命令启动；选择 HR 或 forestry-workorders 创建独立合成项目，
在数据接入页点击“加载当前领域包的合成批次”。这是实际读取 CSV/TXT 并执行规则化，
不自动建模、审核或发布。

第一步进来的是规则化记录和文本。核验画像后看到原值、字段样例和来源位置。
录入明确业务规则、独立答案并冻结本轮会话，再以有权限的身份确认范围。

第二步接收同一范围与来源，构建领域包基线、术语与结构候选。
展示复用/新建的依据，不能把确定性对齐说成 BGE 或 Qwen 运行。
可在“调用已有 LLM 辅助建模”中使用服务器已有配置执行两轮建议；默认明确标为 LLM 检索替代和 Unicode 分块替代。
新 IRI 必须显式列出，留空仅复用。配置、输入与模型收据保存在真实提案中，不显示或提交密钥。

第三步使用真实表格来源和文本模板/片段配置；身份空间决定对象身份。
查看对象与属性关系、所有支持来源和冲突。改映射需要生成新候选，不覆盖旧审核。

第四步选择候选队列运行联合检查，按实际来源逐项人工审核。
严格会话只有全部必需检查通过且候选/依赖摘要一致才能冻结确认包。测试身份不是专家证明。
“模型辅助局部修复与重验”只修正来源支持的属性值/关系目标；展示父版本、修改前后和引文。
新候选自动重验后仍需重新审核。待人工审核是流程状态，不交给模型代替批准；真实未解决事项继续阻断冻结。

第五步选择确认包，提交与第一步冻结内容相同的精确答案，创建编译计划并执行。
SELECT 可显式选择 MULTISET、SET 或 ORDERED；ORDERED 查询必须有顶层 ORDER BY，不能用前端排序伪造查询顺序。
下载真实 `.kgop` 后验证。交付完成仍不是业务发布；进入服务模块继续注册、版本审核与读取。

林业包的任务模块只为“需要复查”创建工单，否定不建单，未知保留待核实。
反馈页提交配置候选、运行回归、人工审核，再启用并重新规划/执行，检查新配置和业务收据。
已有工单不能因重复动作被重复创建。环境版本回滚与执行配置回滚分开记录。

真实截图由 `workbench/tests/zhigou-console.e2e.ts` 输出至相应 browser-runs evidence 目录。
五个页面截图不意味着五个阶段都成功完成；未运行阶段截图应保留 NOT_RUN。
完整 HR/林业工程链和异常验证由独立服务测试给出，不能用未运行页面替代它们。
