# 五步建模工作台

主实现为 workbench/src/stage-console.tsx，旧组件入口仅 re-export。
全局五模块与本体内部五步分开；专注模式收起全局导航。
采用附件 HTML 配色，不接入其原型 JS、前端审批或固定员工输出。

1. 输入核验与范围确认：真实 KG-IR、字段/原文、质量分流；冻结规则、独立答案与输入摘要。
2. 本体复用与结构设计：完整锁定基线；两轮模型复用与补全；新 IRI 需显式允许，所有结果仍是候选。
3. 数据映射与事实构建：声明式映射确定身份；模型只在已知身份/谓词内抽取事实，逐字引文和位置由服务器复核。
4. 联合校验与人工审核：共享编译内核、pySHACL、OWL Profile、HermiT；局部修复生成新版本、自动重验，随后重新逐项人工审核。
5. 语义编译与交付验收：仅编译冻结内容；ASK、SELECT MULTISET/SET/ORDERED 精确预期；验证实际文件和 .kgop，再交接 Registry。

默认展示处理前后表格，可展开所有结果、来源及实际请求收据。模型结构和自动检查分别回显到第二、第四阶段。
连续运行在缺配置或人工审核处暂停。认证恢复不无条件重放动作。

## 模型入口与运行模式

第二/三阶段提供“调用已有 LLM 辅助建模”，第四阶段提供“模型辅助局部修复与重验”。
API 沿用 modeling.proposal，新增 model_assistance，不建立第二套候选、审核或包格式。
必须提供当前严格会话 revision；端点和凭证仅从服务器配置读取，客户端不能提交端点或审批权限。

显式 Qwen 配置优先；存在部分 Qwen 配置时不转用其他 API。
无 Qwen 配置时可用已有 OPENAI_BASE_URL、OPENAI_TEXT_MODEL、OPENAI_API_KEY、OPENAI_RESPONSE_FORMAT。
json_object 模式执行本地 JSON Schema 和引用检查，不冒充服务端严格 Schema 输出。
仅保存公开结构化输出、简短理由和调用信息，不保存模型隐藏推理。

LIVE 请求保留模型声明、观察到的模型 ID、请求 ID、输入/提示/响应摘要、耗时和实际输出。
原 ModelInvocationRecord 契约仍负责录制候选字节，RECORDED_EXTERNAL_MODEL 表示录制层；
另有绑定到 provider snapshot 的 LIVE 链路收据证明本次确实调用 API。录制回放不算 LIVE。

## 效果结论的边界

合成数据上的真实 API/语义编译与安全测试可证明工程链路，不证明专家准确率、留出集表现或研究目标达成。
真实 BGE/FAISS/reranker 权重、OCR/ASR、政务接口与独立专家/标注评测仍需对应环境和资料。
实际结果、失败尝试及受测源码适用范围以 verification.json 与模型验证记录为准。
