# 研究、模块和实现对应

依据为 `docs/reference/zhigou-upgrade/附录/研究内容.pptx`（5 页）和
`知构工具链_本体建模操作台.html`（five-stage-console-v1）。原件不改写。
附件中的实现设想是需求材料，不是已有功能、模型结果或外部操作授权。

| 主模块 | 研究依据 | 唯一实现和边界 |
| --- | --- | --- |
| 数据接入与规则化 | 研究二 | `ingestion/`、`services/sources.py`、`sample_batch.py`；Source、KG-IR、质量、类型化来源位置 |
| 本体建模 | 研究三 | `modeling/control_plane/`、`services/modeling*.py`；范围、结构、事实、审核、确认包 |
| 本体服务与版本管理 | 研究一语义层、研究三末端 | 原 SemanticCompiler、Registry、Release、OMS、对象读取与溯源服务 |
| 任务规划与业务执行 | 研究一执行层 | `services/business.py`；固定包、OMS/对象读取、受控动作、实际工单与收据 |
| 反馈评估与演进 | 研究四 | `services/business.py` 的执行配置分支，以及原 lifecycle 的本体/规则版本分支 |

研究一是组合框架，不是预处理步骤。现有已验证版本可以直接用于任务，
不必每次清洗/建模。任何候选都不能作为正式业务对象写入口。

研究三末端 PPT 叫“本体服务与版本发布”，HTML 第五步叫“语义编译与交付验收”。
前者包含后续服务承接；后者交付 `.kgop`，不自动注册、发布或部署。
本次没有把 Registry、OMS 或 Worker 拆成第二套系统。

## 研究指标保持原义

研究二：项目名称、申请主体等关键字段准确率至少 85%；可比正确性下单位平均处理时间缩短至少 10%。
研究三：对象/属性/关系识别至少 80%；真实专家审核后发布内容至少 90%；来源可追溯完整率至少 90%。
研究四：异常识别至少 80%；业务任务完成率提升至少 10 **个百分点**。
研究一没有统一数字门槛。

当前合成场景仅用于工程验收。未建立足够的独立标注留出集、正式专家审核和可比计时基线，
研究指标保持 `INSUFFICIENT_EVIDENCE`；不得将本地测试角色、固定规则规划或成功工单等同于 LIVE AI 研究成果。
