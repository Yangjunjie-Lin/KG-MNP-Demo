# 本地本体工程流程

先按[安装与启动](../developer-guide/distribution.md)运行 Web 和 Worker，再使用本地管理员签发的凭证登录。没有默认账户，也不能通过选择一个角色取得权限。

## 项目、资料与证据

首屏选择已有项目或创建新项目，并选择明确的 Domain Pack 版本。Minimal、MNP 和 Forestry 使用相同界面；没有权限的项目不会出现在列表中。Forestry 是合成示例，不是实地业务结果。

在“资料与证据”选择文件，上传并登记 Source。文件名仅作展示；服务端计算原始字节摘要。202 仅表示任务已接收，需等待真实 Worker 完成。多文件可选择来源后创建批次，再选择批次生成解析计划并运行。

检查解析状态、质量问题、KG-IR 和 Evidence，打开来源定位并下载原始文件核对。元数据解析、缺 Provider、需审核、失败分别有不同含义；不能把存在一个 Source 当作已经完成解析。

## 建模与人工审核

在“本体建模”填写范围、对象族、目标命名空间和能力问题。范围批准绑定当前修订；发生冲突时重新读取，不自动重试批准。

准备基线与术语、字段或记录映射，并生成候选。Recorded Provider 必须绑定实际上传的 Prompt/Response 原文，它只提供候选，不是在线模型调用或人工批准。

通过表格和有界关系图查看候选与依赖、原始 KG-IR 和证据。逐项填写理由并接受、拒绝或请求修改。修改会产生新的候选身份并重新验证。冲突未解决、依赖被拒绝、审核人数不足时，不能直接生成可编译确认包。

## 编译、下载与发布

在“验证与发布”选择明确的确认包，填写包名称、版本、Ontology/Version IRI，并选择能力问题、锁定包内 Query Asset ID 与明确的 Oracle。结构覆盖不等于查询执行通过；无 Oracle 不得宣称 CQ 已通过。

生成计划后执行真实编译。OWL、SHACL、CQ 和来源验证来自实际工具；缺 Reasoner、约束失败或查询不符合 Oracle 都会阻断成功包。失败任务在“任务中心”查看，不能用一个空结果替代验证成功。

具有 `package:export` 权限的用户可点击“下载已验证本体包（.kgop）”。下载也会再次经过项目权限与 Package 校验；导出不是发布。

验证并导入本地 Registry，创建 Release Candidate，按当前策略进行独立人工审核，最后使用当前 Registry CAS 发布。生产策略要求既有角色类别且至少两名独立审核人；重复点击或同一人的重复批准不会增加人数。

对象浏览必须绑定明确的 Package/Release。查询按服务端限额分页；点击实例和证据返回原始资料，不依赖 GraphDB 才能使用。

## 后续版本、环境与恢复

后续版本通过正常建模、审核、编译产生，不直接编辑 `.kgop`。选择 Base 与 Candidate，执行语义 Diff、影响分析、真实回归和 Change Proposal 评估，再提交后续 Release。

环境切换有独立提案、审核和 CAS。回滚必须选择曾成功激活的历史 Release；旧 Package/Release 保持不可变。`CONTROL_PLANE_SELECTED` 只表示本地指针选择，不等于外部部署。

关闭页面或退出不等于取消后台任务；撤销原凭证会影响任务后续执行和正式提交。取消运行任务只是取消请求，已提交结果不能伪装成撤销。

`RECOVERY_REQUIRED` 时先选择“恢复已提交回执”。只有明确未提交、租约已过期的本地任务可以选择“重试未提交的本地任务”。当前权限、原授权、取消意图和尝试编号都会重新检查；未知外部副作用不能自动重放。

GraphDB 或外部执行器未配置时保持 BLOCKED。Outbox 入队、Pointer 切换和协议测试都不代表真实外部操作完成。
