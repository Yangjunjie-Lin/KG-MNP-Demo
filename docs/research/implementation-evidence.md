# 研究机制、实现与证据

这份对照描述已实现的工程机制，不把立项预期、合成案例或测试计数转换成未经测量的效果。

| 主线 | 实现机制与核心位置 | 行为证据 | 尚未证明 |
| --- | --- | --- | --- |
| 通用、契约化工具链 | `contracts/` 唯一 Catalog；`domain_packs/` 精确 Lock；`services/` 统一请求与权限 | Schema / Lock 篡改与兼容测试，任意名称第四包浏览器测试 | 所有行业通用、学术新颖性、生产规模收益 |

| 候选、审核、编译权威分离 | `modeling/control_plane/` 与 `semantic_kernel/`；服务端身份、修订、审核重放、输入快照 | 未审核不能确认、修改需重验、撤销批准、生产双人审核、真实 OWL / SHACL / CQ / Provenance | 在线 LLM 效果、自动本体学习正确性、业务知识完备性 |

## 案例范围

Minimal 用于完整本地主链路、否定案例和版本/回滚。MNP 使用原领域包的约束及非空合成 MappingRecord，不能以空 ABox 证明通用性。Forestry 0.2.0 包含 6 条树木档案、6 条巡查记录与 2 个地点；它是合成 EXPERIMENTAL 示例，不包含真实私人坐标、专家签名或法定年龄阈值结论。

实际结果应分别读取 Pack、Ingestion、Evidence、Modeling、Review、Compilation、Package、Release 和 Browser 的证据，不用单一“领域包能列出”代替完整流程。

## 指标状态

已测的是具体测试环境、输入规模、执行状态、文件摘要和局部组件渲染耗时。工作台容量测试复用实际组件，输入 1000 条表格记录、250 个合成候选，验证 200 节点 / 400 边上限；这不等于真实业务的吞吐或交互延迟保证。

尚未测量跨机构部署收益、实地林业效果、真实 MNP 业务改进、人工审核时间节省比例、识别模型准确率或行业泛化率。没有对照实验时，不报告提升百分比。

## 验证适用范围

正向、负向、故障注入、浏览器、视觉和平台结果需要绑定同一最终代码修订。途中累积的测试只证明各自检查点；最终收敛台账和发行验收完成前，不宣称整个工具链重构或发行验收完成。
